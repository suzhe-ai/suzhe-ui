# 苏哲 UI

**骨架克制。一页一个主角。元素更少。每台设备都流畅。**

高级感不是特效的叠加。它来自四件事：

1. **克制、一致的骨架**：让人一眼就信任。
2. **每页一个主角**：页面有辨识度，而不是照搬别人的首页。
3. **删掉一切不值得存在的东西**：看着安静，用着省力。
4. **把流畅当成设计的一部分**：再好看的页面，也要在便宜手机和旧笔记本上同样流畅，才算顶级。

下面每一条规则都来自一个线上网站的真实改版。被否掉的尝试和失败原因见 [`references/rejected.md`](references/rejected.md)。

本 skill 的说明用英文写成；页面文案用用户的语言写。中文页面请看 §1 里的 CJK 排版规则。

---

## 0. 开工前：页面类型与语气

| 页面类型 | 例子 | 语气 | 指南 |
|---|---|---|---|
| 品牌 / 展示页 | 首页、商店、产品页、活动页 | 商务 | §1–§4 |
| 身份时刻 | 登录、注册、关于我们、分享卡片、品牌宣言 | 编辑 | [`references/page-types.md`](references/page-types.md)（D） |
| 正式页 | 公告、条款、调研、帮助与 API 文档 | 文档 | [`references/page-types.md`](references/page-types.md)（B） |
| 工具页 | 邮箱、后台、控制台 | 工具 | [`references/page-types.md`](references/page-types.md)（C） |
| 流程页 | 结账、兑换、表单 | 商务 | [`references/page-types.md`](references/page-types.md)（D） |

在条款页上炫技显得不正经；给工具换皮解决不了任何问题；把结账打扮成营销页会让人紧张；用商店配色做登录页会显得冷冰冰。**一个页面，一种语气。** 各种语气共用间距、动效和焦点规则。

## 1. 骨架

先把 [`references/tokens.css`](references/tokens.css) 拷进项目；下面所有数值都在里面。

### 商务语气（默认）
- **只有三种底色**：白 `#fff`、浅灰 `#f5f5f7`、黑 `#000`。**相邻区块必须不同**：区块之间靠底色分隔，不靠边框或分割线。白和 `#f5f5f7` 在缩略图里几乎分不出来，所以要用代码验证（[`references/checklist.md`](references/checklist.md)）。
- **文字只用灰阶**：主文字 `#1d1d1f`，次要 `#6e6e73`，说明 `#86868b`；黑底上用 `#f5f5f7` 和 `#a1a1a6`。绝不用纯黑文字。
- **只有一个强调色**：蓝 `#0071e3`，只用于主按钮、链接（`#0066cc`）和焦点环。可以用一个暖色眉标颜色（`#b64400`）标记标签。
- **系统字体栈**：苹果设备上用 SF / 苹方（无需下载），其他平台用 Inter + Noto Sans SC。标题字重 600；西文标题越大，字距越紧（−0.015 到 −0.03em）；**CJK 字距保持 0**。正文 17px / 1.47。层级来自字号、字重和灰度，而不是框。绝不打包商业字体。
- **双色标题**：前半句用墨色说「是什么」；后半句用灰色说「为什么」。
- **胶囊按钮**（`border-radius: 980px`）：每个区块一个蓝色主按钮；次要操作用描边胶囊按钮，或「了解更多 ›」文字链接。
- **卡片随底色而定**：灰底区块里放带淡阴影的白卡；白底区块里放不带阴影的灰卡。圆角 18px，悬停上浮 3px。
- **毛玻璃只给浮在内容上面的东西**：导航、底部购买栏、toast。绝不用在卡片或区块上。
- **尺寸**：内容最宽 1120px，左右边距 22px（手机 20px）；区块上下内边距 96/104px（手机 64/72px）。首屏高度是视口高度减去约 120px，让下一块的标题露出来；整屏通栏约 600px 高。断点与 apple.com 一致：734px 和 1068px。
- **第三方品牌色只做点缀**：眉标颜色、一个渐变字、一团柔光、一个 App 图标式的圆角图块。绝不整块铺品牌色，也不在商务页面里突然换成衬线字：那样看起来像是从别的网站剪下来贴上的。彩色横幅之间留 12px 白缝。

### 编辑语气（身份时刻）
在页面根元素加 `class="editorial"`。
- 默认暖黑 `#141413`，系统是浅色时用暖纸白 `#faf9f5`；在 `<head>` 里内联底色，避免白闪。
- **衬线大字**只用于那一句大宣言（字重 500，`clamp(40px, 4.2vw, 62px)`，`text-wrap: balance`）；其余全部仍用系统黑体。衬线字只取页面用到的字形做子集。
- **墨色按钮，不用蓝色**：主按钮把文字颜色反相（纸白底上是黑色，暖黑底上是白色），圆角 10px，高 44px。
- 1px 细边框，24px 圆角卡片，不加重阴影。一个暖色点缀，每页最多出现一次。

## 2. 主角（不是 apple.com 的复刻）

只有骨架，看起来就是「苹果的仿品，只是更廉价」。主角才是让人记住的东西。

- **选一个属于这个产品、这项任务的视觉。** 先问：这个产品独特在哪里？用户在这里必须完成什么？从这两个答案里长出主角。下面的方向只作启发，**绝不照抄**，否则每个网站的登录页都会长得一样：
  - 登录：品牌对用户说的一句话，旁边配一段真实产品的短片；
  - 商店首屏：产品本身，用 3D 渲染，或者一个会转动、会切换的实物；
  - 兑换 / 长任务：把进度画在品牌标志本身上（见 [`references/motion-perf.md`](references/motion-perf.md)）；
  - 文档：排版本身就是主角。
- **绝不在两个页面上重复使用同一个主角**；那会被看成偷懒。
- **质感来自材质和光**：拉丝金属、颗粒、层叠阴影、虹彩边缘、跟随光标的高光、3D 产品渲染，而不是白卡加扁平的蓝按钮。
- **一页有多张品牌横幅时**：每张都在骨架之内做出不同的构图和材质。从这个品牌自己的呈现方式出发。
- **不要做**：大面积光雾或光晕、装饰性的地平线、与内容无关的动态背景。

## 3. 少（内容与元素）

- **隐藏不可用的东西。** 缺货、下架或禁售的项目不显示；整组为空就整组隐藏。灰掉的卡片会让页面显得乱。
- **帮助文案只写一句**：打开什么、复制什么，入口可见、可点。不主动加教程卡片、FAQ 或示意图。只有真正有分支的流程，才值得放一张节点文字很短的小流程图。
- **结果页只显示结果**，别的都不放。每多一句话，就多一处可能被误读；规则应该写在条款里。
- **用正面表述**（「包含 X」），不要堆一串否定和免责声明。
- **能一步就一步**：让人直接选，而不是「先进入某个模式，再选」。
- **不要在文案里露出让人犹豫的数字**，比如手续费比例或内部流程。

## 4. 时机（交互时序）

- **提示只在需要时出现。** 校验错误在提交之后出现，紧挨着出错的字段。人机验证在后台静默运行，主要输入填完后才出现，只有用户确实漏了才提示。绝不提前吓人，也不让人干等。
- **长任务显示真实进度**：有名字的阶段，按真实时钟计算，标签页被隐藏时也照常前进。耗时比平时长时，换一句安抚的话。
- **完成要「亮」，不要「炸」。** 失败要说明后果（「次数已退回」），而不只是一个红色报错。
- **动效只标记状态变化**：出现、展开、完成、失败。默认缓动 `cubic-bezier(.28,.11,.32,1)`；只对 `transform` 和 `opacity` 做动画。**每页最多一个循环动画**，离开视口就暂停。重特效按设备分档降级；尊重 `prefers-reduced-motion`。见 [`references/motion-perf.md`](references/motion-perf.md)。
- **正常状态不加标记，只标异常**：库存正常时不显示圆点，紧张时显示橙色（没货时按 §3 整个隐藏）。

## 5. 一致（多页面、多子站）

- **品牌设计变量全站统一**：标志、字体、焦点颜色、favicon。布局、语气和主角可以不同，设计变量不能不同。
- **标志是透明底上的单色图形**，深色模式下反色。**绝不把它放进圆角方块里**：深色模式下它会变成白色方块里的黑色图形。
- **同时支持深浅色的页面默认跟随系统**，并记住用户的手动选择。只设计了浅色的页面，不要硬加深色分支。
- 「统一视觉」是统一设计变量，不是把每个页面都塞进同一个布局。
- **增量改进。** 绝不一次性重做一个大家已经用得舒服的页面；一次改一个区块，上线，验证。大改版先做本地预览，附上截图。

## 6. 工作流程

1. 确定页面类型和语气（§0）。
2. 用一句话说出主角：它是什么，和这项任务有什么关系。
3. 排出各个区块和它们的底色；检查相邻区块不同。
4. 粘贴 [`references/tokens.css`](references/tokens.css)；按 [`references/components.md`](references/components.md) 搭组件。
5. 删减：对每个元素、每一句话都问「没有它，用户会失去什么？」答不上来就删掉。
6. 用 [`references/checklist.md`](references/checklist.md) 验收：390px 下没有横向滚动，相邻底色不同，控制台 0 错误，键盘焦点可见，CPU 降速后依然流畅。
