# 被否掉的做法（反例集）

这些都是真实改版中被否掉的方案。改版、做新页面之前读一遍：它们的共同点是「看起来很用力」，但让页面显得乱、像别家、或者不可信。每条都写了**为什么不行**和**后来怎么改对的**。

---

## 1. 硬抄 apple.com

- **做法**：48px 导航 + 首屏 3D 图标弧 + 白卡 + 蓝色胶囊按钮，原样照搬商店首页的版式去做登录页。
- **评价**：「很明显模仿了苹果官网，但效果一般，说不出哪里不好，就是质感差点」「跟主站重叠」。
- **为什么**：用户要的是**有辨识度**的高级感，不是平面复刻。同一张主视觉在两个页面都出现，会被看成偷懒。
- **中间一版**：左边深色舞台上放一张金属质感的「账户卡」，输入的邮箱刻在卡面上、跟着鼠标倾斜；右边白底表单。有了主角，但仍是商店那套冷色骨架。
- **最终定稿**：换成**编辑语气**：暖纸白（深色模式是暖黑）底，左边一句衬线大字 + 细边框表单卡，右边是产品自己的短视频，主按钮用墨色。登录是用户和品牌的「身份时刻」，需要温度和信任感，不需要商店的热闹。
- **教训**：设计变量（间距、动效、焦点规则）全站一致，**语气按页面的角色来定**。卖东西的页面用商务语气，身份时刻用编辑语气。（以上都是这个产品当时的答案，不是模板。）

## 2. 整块品牌色铺底

- **做法 A**：第三方品牌的通栏横幅用「白→橙渐变 + 3D 图」。评价：「审美太垃圾」。
- **做法 B**：整块陶土色铺底 + 衬线字 + 大号品牌标志做背景。评价：「跟背景不搭配」。
- **为什么**：全站是黑 / 白 / 浅灰三种底色。一块品牌色或者一套衬线字插进来，就像从别人网站剪下来贴上的。
- **改对**：黑底，底部加一点品牌色柔光，字体还用系统黑体，按钮还用站内的蓝色胶囊；品牌标志做成苹果 App 图标那样的圆角图标。品牌感只靠点缀。

## 3. 新横幅套用上一张横幅的模板

- **做法**：新商品横幅照抄已有横幅的构图（居中标题 + 立体字 + 商品图），只换了商品。
- **评价**：「请不要跟上一个一样，一个模板」。
- **为什么**：同一页上的几张横幅如果长得一样，就失去了区分度，看起来很廉价。
- **改对**：先想这个品牌自己的官网长什么样：是插画还是摄影，左文右图还是居中构图，材质是纸面还是金属。然后在全站骨架里做出差别：底色、字体、按钮不变，构图、主图和点缀换掉。

## 4. 正式页面上炫技

- **做法**：公告 / 投票页用了动态线条背景 + 玻璃卡片 + 渐变大数字。
- **评价**：「现在的排版像是个笑话」，要求按 API 文档、上市公司官网的正式排版来做。
- **为什么**：公告、条款、调研、文档这类页面，要的是**可信**。炫技会显得不正经。
- **改对**：纯色底，14–15px 正文，行高 1.75～1.9，细线表格，眉标用强调色小字，支持浅深两种主题。参见 `page-types.md` 的「正式页」。

## 5. 教程式帮助 UI

- **做法**：用户不知道某一步该去哪个网址，于是做了「三步卡片 + 模拟页面预览 + 一键粘贴 + 折叠 FAQ」。
- **评价**：「太复杂了，乱七八糟」。
- **为什么**：用户卡住的根本原因只有一个：**不知道打开哪个网址**。把网址本身摆出来就解决了，其他东西都是噪音。
- **改对**：一句话（「登录后打开这个网址，全选复制，粘贴到下方」）+ 网址框 + 打开按钮。看不见的容错逻辑（比如粘错了自动诊断）可以保留，因为它不占版面。

## 6. 把缺货 / 不可用项灰着显示

- **做法**：缺货商品灰显后排到末尾，整类缺货的类目沉到底部。
- **评价**：「缺货的就不要显示了，乱七八糟的」。
- **为什么**：一排灰卡、一整块灰类目会拉低整页的质感。干净比「让人知道有这个东西」更重要。
- **改对**：不可用就不显示，整组都不可用就整组隐藏。

## 7. 相邻区块用同一种底色

- **做法**：新加的区块照抄上一块的白底，结果两块白底连成一片。
- **评价**：「看起来没有效果」。
- **为什么**：页面是靠底色交替来分区的。白（#fff）和浅灰（#f5f5f7）在缩略截图里几乎看不出差别，**光看截图发现不了**。
- **改对**：新增、隐藏、移动区块后，用代码逐块读出背景色，确认相邻两块不同（见 `checklist.md`）。

## 8. 把支付 / 结账做成品牌营销页

- **做法**：把轻量的结账弹窗重做成一整页「品牌官网式」支付页（纸面收据、三步进度、盖章动画）。工程质量满分，跑分全过。
- **评价**：「怎么感觉没有现在线上的版本舒服，看起来更像品牌支付页面」，随后整个方案作废。
- **为什么**：付款时用户只想快点、放心地付完。营销式的层级和厚重的视觉会增加负担。
- **改对**：保留弹窗形态，二维码、倒计时、订单摘要一眼就能看到。如果要参照，参照的是「苹果的支付页」：白底、单栏、大留白、几乎没有装饰。

## 9. 工具界面只换配色

- **做法**：邮箱界面改版时只换了颜色、改了点排版（白色换成黑色）。
- **评价**：「你做的是什么东西」，要「像谷歌系统那样、像上市公司一样」。
- **为什么**：工具类界面的好坏取决于**布局和交互**：能不能快速搜索、分类、找到东西。换皮不解决问题。
- **改对**：照 Gmail / Google 账号页的布局和白底浅色重做，重点放在搜索、分类和信息密度上。

## 10. 提示出现得太早，或者太晚

- **做法 A**：一进入密码步骤，就显示「正在进行安全验证…」和验证框。评价：「用户还没点击，不能直接就显示请安全验证」。
- **做法 B**：点了「继续」才开始验证，验证框和警告一起冒出来。评价：「逻辑错误」。
- **改对**：一进入这一步就在后台静默验证，验证框先藏起来；主要输入填完后它才自然出现（大多数人会静默通过，什么都看不到）；只有用户点了提交、却确实漏了验证，才显示提示并轻晃一下。
- **原则**：提示只在用户真的漏了的时候出现。不要提前吓人，也不要让人干等。

## 11. 只听「统一成白色」就改掉跟随系统

- **做法**：听到「默认白色」，就把几个支持深浅色的子站改成固定浅色。
- **结果**：当天恢复。真正的要求是**默认跟随系统**，用户手动切换后记住用户的选择。
- **例外**：本来就只设计了浅色的品牌页和工具页（例如邮箱），不要硬加深色分支。

## 12. 交付 / 结果页附加「好心提示」

- **做法**：在交付结果下面加了一句好心的「下一步建议」。
- **结果**：这句建议和商品说明里的规定互相矛盾，引发用户纠纷。
- **原则**：结果页只显示结果本身。规则写在商品说明和购买须知里，不要散落在各个页面。

## 13. 首屏放重特效却不分档

- **做法**：首屏放了约 1600 个粒子，每帧画两遍，加上叠加混合和遮罩，一直在跑。
- **结果**：好电脑上 0.5ms 一帧，完全看不出问题；但在软件渲染加慢 CPU 的设备上只有 23 帧，明显卡顿。
- **改对**：按设备分三档（原样 / 减半 + 30 帧 / 静态图），起步时先检测一次，运行中再测，只降档不升档。见 `motion-perf.md`。

## 14. 庆祝不克制

- **做法 A**：长任务的进度动画中间放了一颗 WebGL 能量球。评价：「中间这个球不好看，这个动画也不高级」。
- **做法 B**：完成那一下用实心色块填满、中心火花爆炸、加一圈硬边白环。评价：「过程很喜欢，成功那下不高级」。
- **改对**：把进度画在品牌标志上：标志先是淡线稿，一支发光的笔沿着轮廓一笔笔「刻」出来，刻到哪里，进度就到哪里。完成时笔头化成光，沿着刻痕向外漫开，加少量光尘和一圈柔光涟漪。全程只用黑、白和一个点缀色。
- **原则**：完成时刻要「亮」，不要「炸」。

## 15. 把已经好用的页面整页重做

- **做法**：三次分别把激活页、支付页、商店首页整页推倒重做，每次都是一套新理念、新骨架，工程质量也都很高。
- **结果**：激活页上线当天回滚（「还是喜欢原来的 UI」）；支付页没上线就被叫停（「没有现在的版本舒服」）；商店新版上线后整体回退，只留下了其中一个局部（一个品牌字标）。
- **为什么**：用户已经熟悉、觉得舒服的页面，整页重做的风险远大于收益。
- **改对**：增量打磨。一次改一个区块，单独上线、单独验证；大改版先做本地预览，让人看过截图再决定。

## 16. 分享卡片选「惊艳」还是「克制」

- **做法**：给网站做社交分享预览图，第一版是深色宇宙背景、多色光晕、产品渲染图铺满，很惊艳。
- **结果**：最后选的是极简版：象牙白底、一行细衬线字标、一行宽字距的大写副标，别的什么都没有。
- **原则**：惊艳可以拿来看，长期代表品牌的东西选克制。
